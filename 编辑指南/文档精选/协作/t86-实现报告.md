# T86 实现报告：引擎菜单顶栏缺失修复（DPI 贴窗放大根因）

## 现象（t85 证据 ①）

- 用户「显示不全」实测定位：引擎菜单顶栏（👤玩家/⚙设置/✖退出 整组）未渲染——右上区（x2100..2560 y30..160）全空；功能卡看似只剩单列（右缘 7 张宽卡，未见第 2 列）。
- t85 结论「t63 布局自定义后顶栏未绘」是表象归因；实际为**渲染层 DPI 贴窗放大**，顶栏/右列被推出窗口外。

## 根因（逐像素质证）

交互窗口 OnPaint 渲染路径（EngineMainShell.cs）：

1. `_gdiBmp = DpiBitmap.Create(w, h)` —— t78 起固定 **96 DPI** 位图（2538×1472 物理客户区尺寸）。
2. 内容按 letterbox（scale=1.84）画进 `_gdiBmp`（顶栏在画布 x≈930..1270 → 位图 x≈1803..2425）。
3. 贴窗用 `e.Graphics.DrawImageUnscaled(_gdiBmp, 0, 0)` —— **e.Graphics 是 150% 缩放 (144 DPI) 的设备 Graphics；GDI+ DrawImageUnscaled 按图像 DPI vs 设备 DPI 换算：96-DPI 图像在 144-DPI 设备上被放大约 1.5×**（实测：96-DPI 100×100 色块 → 144-DPI 图形上画成 152×152）。

   结果：整帧被放大 1.5×（2538×1472 → 3807×2208），窗口只显示左上 2538×1472：
   - 顶栏（位图 x≈1803..2425 → 设备 x≈2703..3639）**整组出窗**；
   - 功能网格第 2 列（位图 x≈1361..1786 → 设备 2042..2679）超窗出右缘；第 1 列右端也被裁——t85-01 只见「单列宽卡」+ 右缘无字；
   - 我的截图（t86-pre-fix-full-window.png）与 t85-01-menu.png **逐像素一致**（复现）；`--shellshot`（RenderPageTo 直接 `c.Render(draw)`，无 e.Graphics 贴窗）顶栏正常 —— 与此前「shellshot 有顶栏、交互窗没有」的矛盾完全吻合。

## 修复（EngineMainShell.cs）

1. **OnPaint 贴窗改为 DPI-精确 1:1**（t86）：
   ```csharp
   var blitState = e.Graphics.Save();
   e.Graphics.PageUnit = System.Drawing.GraphicsUnit.Pixel;
   e.Graphics.DrawImage(_gdiBmp, 0, 0, _gdiBmp.Width, _gdiBmp.Height);
   e.Graphics.Restore(blitState);
   ```
   显式目标尺寸 + Pixel 单位 = 物理像素 1:1（实测像素单元绘制 100×100 原大；无 1.5× 放大、无插值模糊）。

2. **_backdropBmp 改 96 DPI**（配套）：DrawBackdropCached 里 `new Bitmap(w,h)`（默认 144 DPI）在 96-DPI 适配器上 DrawImageUnscaled 会被缩到 2/3；改 `DpiBitmap.Create` 与 _gdiBmp 同口径。

> 不改变任何布局/坐标/字号；仅修贴窗换算。letterbox scale=1.84 仍按物理客户区原生渲染（t27/t79 语义不变）。

## 结论

- t85 五元组「顶栏缺失」根因= **t78 96-DPI 位图 + DrawImageUnscaled 在 150%-DPI 设备上的 1.5× 贴窗放大**（t63/布局无关）。修复后交互窗与 shellshot 布局完全一致，用户「显示不全/顶栏不见」消除。
- 此修复同时保障了此后任何页面（选歌/设置/次级页）在交互窗的正确性（同贴窗路径）。
