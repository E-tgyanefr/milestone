# t31 实现报告：根治 emoji 推进宽（按实际绘制宽推进 + 6px 保底间距）

- 日期：2026-08-27 · 承办 coder-max · 约束：只写代码不构建（captain 构建 + 试玩多尺寸 gap 复验）
- 依据：t30 实证（visual-sweep-icontext.md：scale 2.02 gap 7px → 1.52 gap 4px，更小缩放归零）

---

## 实证（GDI 探针，20pt 🎵 U+1F3B5）
- MeasureString(YaHei)=28.0px；MeasureString(**Segoe UI Emoji**)=**46.6px（≈2.33em）**；
- 旧推进=码点×字号×1.15=23px——图标实际画 ~46px 宽却只推进 23px → 后随文字压进图标内（t28 P1 机制实锤）；
- 修后推进=46.6+6 → gap≥6 恒成立。

---

## 每适配器改动

### 1. GdiDrawAdapter（Text + MeasureText）
- emoji run 推进/测量：`_g.MeasureString(run.Text, emojiFont).Width + 6`（emojiFont=Segoe UI Emoji，即 run 自身字体 f）
  ——测量=推进=绘制同口径；+6px 为保底间距（任意缩放 gap≥6）。常规 run 不变。

### 2. D2DDrawAdapter（Text + MeasureText）
- emoji run 推进/测量：`_r.MeasureText(run.Text, sz, UiGlyphRuns.EmojiFont) + 6`——TextLayout 在该字体下真实 advance；+6 保底。

### 3. D2DRenderer.MeasureText（支撑 D2D 真实测量）
- ①逐**码点**缓存（代理对整对测量）——旧逐 UTF-16 单元测孤立代理失真，emoji 整对 advance 无法正确测得；
- ②缓存改**多桶**（family|字号档 各一桶，上限 8 桶，超限清空）——emoji/常规 run 交替测量时不再互相清桶
  （旧单桶每帧清空→逐帧重测 TextLayout，188 emoji 标签下会是每帧 COM 分配热点）；
- CHART_NO_CHARCACHE 诊断门保留（全串 TextLayout 路径不变）。

### 4. UiGlyphRuns.MeasureRuns（引擎侧统一口径）
- 全部委托后端 `d.MeasureText(run.Text, sz)`——emoji 估宽公式（1.15em）从引擎层彻底移除。

### 5. UiMeasure（t29 宿主测宽，构建期 FitFont/ButtonWidth 用）
- Width 与适配器同口径：run-split，emoji run 用 Segoe UI Emoji 测宽 + 6——构建期字号适配与运行时推进一致。

### 保持不动
- t29 双标签拆分（选歌 ♪ 8px、玩家信息 ⚙）保持不变——间距语义不受新推进宽影响。
- 纯文本快速路径（无 emoji）零改动。

## 回归预期
- 188 处 emoji 标签：推进=真实绘制宽+6 → 任意缩放图标-文字 gap≥6（t30 全尺寸扫描口径）。
- 测量类（AutoShrinkFont/居中/Ellipsis/FitFont）：测量=推进=绘制三端一致 → 数学零回归；
  仅 emoji 所在标签宽度按真实值增大（图标处像素变化，即任务预期「标准场景截图 sha 仅图标处变化」）。
- 性能：D2D 多桶缓存稳态零 TextLayout；GDI 侧 emoji run 多一次 MeasureString（每帧每 run 一次，与常规 run 同量级）。
