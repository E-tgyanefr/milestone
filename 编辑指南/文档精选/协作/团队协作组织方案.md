# 团队协作组织方案(游戏内容 AI 起草 · 2026-08-21)

> 用户反馈:"你们似乎无法做到真正的团队合作,请组织"。本方案建立三方(策划/引擎AI/游戏内容AI)的**任务闭环流转机制**,解决"策划只出文档、引擎闲置、主代理单干"的问题。

## 1. 三方角色与领地(不变)

| 角色 | 领地 | 职责 |
|---|---|---|
| 策划(DeepSeek A) | `策划\` | 定需求/规格/验收标准;**审阅实现并反馈** |
| 引擎 AI(DeepSeek B) | `engine\` | 引擎层能力/判定闭环/API;**响应指令并回报** |
| 游戏内容 AI(主代理,我) | 项目根 .cs + `游戏内容\` | 玩法/渲染/编辑器/解析;**接收双方输入并落地** |

## 2. 问题诊断

1. **策划**:产出规格文档后无"验收反馈"环节——不确认我实现得对不对,后续需求也不推进(E-3/E-1 挂起)。
2. **引擎 AI**:指令 4 完成后闲置——无新指令下达,也不知道主项目侧已接入其 tick API。
3. **主代理(我)**:长期单干,因为没有等待机制;两个 AI 的产出未被及时消费。

## 3. 协作闭环机制(本次组织落地)

### 3.1 任务板(新增 docs\协作\任务板.md)
统一状态表,三方各占一列,任务项含:状态(待策划/待引擎/待主代理/验收中/完成)、负责人、依赖、验收标准。

### 3.2 流转规则(写入协作守则)
- **策划**:每份规格文档尾部加"验收清单"栏;规格定稿后在消息板 @主代理 明确"请实现 X,验收标准 Y";实现完成后**必须审阅并反馈**(确认/驳回)。
- **引擎 AI**:指令完成后在消息板回报;主代理(或策划)在 `指令.md` 下达新指令,引擎 AI 执行后 `done` 触发自动验收。
- **主代理(我)**:每轮检查任务板;策划/引擎有输入立即处理;完成一项后更新任务板状态并 @对方验收。

### 3.3 本轮立即下达的任务(打破闲置)

| 任务 | 给谁 | 内容 | 依赖 | 验收 |
|---|---|---|---|---|
| T1 | 策划 | 审阅 ADOFAI 实现(11 项对齐)并确认/驳回;产出 **E-3 Cytus page 规格** | — | 规格文档+留言 |
| T2 | 策划 | 产出 **E-1 Phigros 关键帧曲线规格**(可分期:先曲线可视化+拖拽) | — | 规格文档+留言 |
| T3 | 引擎 AI | **指令 5**:maimai RingField 判定对接主项目(DrawMaimai 判定窗口/RingNote 滑动进度 API 验证)+ 引擎 README 补 ADOFAI 双球/判定样例 | 无(引擎独立) | DemoRunner 断言+验收 |
| T4 | 主代理(我) | 等 T1 反馈修正;T2 规格到位后实现 E-1 首期;humantest 回归待弹窗允许 | T1/T2 | 构建 0 错误+留言 |

### 3.4 守望机制
- 现有后台:pwsh-3(引擎监控 10s)、pwsh-5(舵手 watch 15s 汇总待办)——继续运行。
- 主代理每轮:检查消息板/策划目录/验收反馈 → 处理 → 更新任务板 → 留言。

## 4. 第一步(本方案落地即执行)

1. 创建 `docs\协作\任务板.md`(上述任务初始化)。
2. 消息板 @策划:请审阅 ADOFAI 实现 + 产出 E-3/E-1 规格(附验收清单)。
3. 消息板 @引擎AI:下达指令 5(写入指令.md)。
4. 主代理:等双方响应;响应到达即处理,处理完更新任务板。
