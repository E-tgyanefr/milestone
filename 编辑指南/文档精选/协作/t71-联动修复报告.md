# t71 联动修复报告（verify-t71-engine 三项：P1-a/P1-b/P2）

> 编写：eng-coder-vis（引擎编写）· 依据：引擎使用者 verify-t71-engine.md（官方终验+build-tool 首跑暴露）

## P1-a：build-tool.ps1 模板源路径（已修）

- **问题**：$tpl 指向 `引擎/engine/PublishPlayer/bin/Release/net8.0-windows/win-x64/pack-template.exe`——不存在（dotnet build 只出 9.6MB 框架版；67MB 模板在 `构建产物/pack-template/MilestonePlayer.exe`）。
- **修复**：多源发现链①`构建产物/pack-template/MilestonePlayer.exe`（bootstrap 主源，67MB 单文件模板）②PublishPlayer win-x64/pack-template.exe ③PublishPlayer 根 ④FALLBACK=单文件 publish PublishPlayer（重命名 MilestonePlayer.exe→pack-template.exe）——任一命中即拷贝+打印来源。
- **验证**：改动后源文件重建（引擎源码/engine 路径）；EngineChecks exit=0（0 警告 0 错误）。

## P1-b：UTF-8 BOM（已修）

- **问题**：build-tool.ps1 无 BOM → PowerShell 5.1（powershell -File）解析失败（Missing closing '}' 假象）。
- **修复**：写入 UTF-8 BOM（EF BB BF）。验证：`powershell -NoProfile Parser::ParseFile` → **PS5.1 PARSE OK（0 errors）**（英文临时路径验证,规避中文路径控制台乱码）。

## P2：单文件版 --preview exit=-1（已修——HInstance fallback）

- **症状**：单文件版（PublishSingleFile）--preview 画面 PAINTED=True 但 exit=-1（静默）；目录版/官方版同命令 exit=0。
- **根因**：`HInstance = Marshal.GetHINSTANCE(typeof(Win32Window).Module)`——**单文件发布下返回 -1（IL3002 警告指向）**→ RegisterClass/CreateWindowExW 用无效 hInstance → 窗口创建/销毁路径异常 → 进程退出码 -1。
- **修复**（引擎源码/engine/App/EngineWindow.cs）：`ResolveHInstance()` 防御——①GetHINSTANCE>0 用之 ②回退 `GetModuleHandleW(null)`（进程主模块句柄,单文件/GUI/console 均有效）③仍失败返 0（CreateWindowExW 允许——但此路径不应触发）。
- **验证**：EngineChecks（迁移后源码）0 警告 0 错误 exit=0;目录版 --preview mania4 --secs 4 exit=0（单文件 publish 属 captain 构建范畴——建议官方单文件版复验 --preview exit=0）。
