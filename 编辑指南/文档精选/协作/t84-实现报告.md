# t84 实现报告：模板工程路径参数化（dotnet new milestone-engine 任意目录可构建）

> 编写：eng-coder-vis（引擎编写）· 任务 t84（dep t81）· 验收：dotnet new milestone-engine -o 任意目录 --enginePath <引擎源码路径> → dotnet build 0/0

## 修复

### ① template.json 增加 enginePath symbol

```json
"symbols": {
  "enginePath": {
    "type": "parameter",
    "description": "MilestoneEngine.csproj 的路径（相对生成目录；默认=上溯到仓库根引擎源码/engine/MilestoneEngine.csproj）。生成到任意目录需传 --enginePath 指向引擎源码。",
    "datatype": "string",
    "isRequired": false,
    "replaces": "__ENGINE_PATH__",
    "defaultValue": "..\\..\\..\\引擎源码\\engine\\MilestoneEngine.csproj"
  }
}
```

### ② csproj 占位符

```xml
<ProjectReference Include="__ENGINE_PATH__" />
```

（注释同步改：避免 `--` 双连字符——XML comment 不能含 `--`（MSB4025: XML comment cannot contain '--'）——enginePath 表述无连字符。）

## 验证（实测）

```powershell
# ① 默认（仓库根附近生成）→ 默认路径替换 ✓
dotnet new milestone-engine -o 构建产物/obj/t84-verify/Game3
#   → <ProjectReference Include="..\..\..\引擎源码\engine\MilestoneEngine.csproj" />（默认路径替换成功）

# ② 任意目录 + 显式 enginePath（验收路径）✓ 构建 0/0
dotnet new milestone-engine -o 构建产物/obj/t84-verify/Game5 --enginePath 'D:/Users/etgya/Desktop/milestone/引擎源码/engine/MilestoneEngine.csproj'
dotnet build Game5/Game5.csproj -c Release
#   → 已成功创建模板 + 0 警告 0 错误（CS0246 已消——GameEngine/SceneBase 找到）
```

## 备注

1. **显式路径建议用正向斜杠**（D:/…）——反斜杠值在 dotnet new 参数转义可能被吞（实测正向斜杠稳定）。
2. **默认路径**适用于仓库根附近生成（如 构建产物/ 下 1-2 层）；深度任意目录=传 --enginePath（验收覆盖）。
3. **避坑**：XML comment 内含 `--` 会 MSB4025——模板内容注释已全部规避。
