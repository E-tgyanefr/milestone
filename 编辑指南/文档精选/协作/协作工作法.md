# 协作工作法（铁约定 · 2026-08-22 用户定稿）

> **用户指令：以后都按此方式执行。**
> 角色：**协助 AI 写代码，主代理只负责监督与核实**（出规格 → 它写 → 我编译/测试验证 → 它修(≤2轮) → 监督裁决 → 如实记录汇报）。

## 工作环（每项任务循环）
1. **规格**：主代理写精确规格（签名/输入输出/阈值/约束/示例；只允许它产出 ≤40 行的小原子件——其可靠区间）。
2. **它写**：协助 AI 输出代码（限定 ```csharp 块；要求 ASCII 字符串，其输出中文会变 `?`）。
3. **我核实**：编译 + 对应测试（--selfcheck / --ratingtest / --reviewtest / --coachtest / --libraryrating，按项取舍）+ 行为抽查。
4. **它修**：失败则把编译器/测试错误原样回传，最多 2 轮。
5. **监督裁决**：若其逻辑正确但被环境缺陷破坏（如中文→`?`、思考超支截断），由主代理按规格还原/裁剪，**在代码注释与消息板写明归属**；不粉饰。
6. **记录**：任务板（谁写谁核、状态、验收项）+ 消息板留言 + 结果文档。

## 分工边界
- 它写：原子件逻辑（纯函数/小方法）、单元化数据转换、逐条规格可对照的代码。
- 我写：规格编制、集成胶水（多文件/UI 上下文/编译全局视角）、测试与验收、文档。
- 它审：开放式的单文件代码审查（其已验证强项），作为集成后的复核。

## 硬约束
- 每项改动后过验证工作流；破坏段位序（--ratingtest）等已验收结论视为失败。
- 全程记录真实结果（成功/失败/截断/缺陷），供用户随时核查。
- 用户可随时调整分工；调整即时生效并更新本文档。

## 附录A：环境隔离 vs 引擎判定 判别法（2026-08-29 收进；B2 全过程沉淀）
> 适用：自动化测试环境报告「输入/UI 不可达」而引擎侧代码断言全绿时的定性流程（避免把环境限制误判为引擎 bug，或反之漏掉真 bug）。

1. **时间线核对**：源文件 mtime vs 各 bin 内 dll/exe mtime——先排除「bin 陈旧」这一最常见假象（B2 教训：官方 dll 01:17:59 < 源码 07:10:36=缺桥；含桥起点 07:10:44）。
2. **路径确认**：测试所用 exe+dll 完整路径与时间戳一并登记（同目录配对），杜绝「测得不是那个构建」。
3. **日志探针**：生产层三处日志（WndProc 收到 → 事件 Invoke → 宿主入口）二分定位；外加 hwnd 身份钉死（Title/ClassName/Rect）+ 残留窗口清场 + Key 对照组。
4. **winsta 隔离判定**：若 WindowFromPoint 命中目标窗、消息确实进窗，但合成/真实输入在自动化会话仍不可达（键盘偶达/鼠标统一不可达），判定=测试会话与桌面 winsta 隔离——**限制性证据不入引擎判定**；终确认=引擎侧证据链（断言+对照路径实测+生产日志）或人工真机点睛。
5. **归档**：全证据（报告+截图+日志）与「终判=引擎 OK/环境限制」结论一同留存；衍生 UX 项（如占位按钮误导）登记 backlog。
6. **终极补充（B2 收官定案，2026-08-29）**：跨进程 WM 投递（SendMessage/PostMessage）客户区坐标会被**系统 DPI 缩放**（PerMonitorV2：投 (335,311) → WndProc 实收 (223,208) ×0.667）——投递侧需**DPI 反向补偿**（×Dpi/96）后再测；补偿后（投 503,467 → WndProc 335,312 → virtual 326,330）跨进程窗口级导航**实证成功**。教训：一切「窗口级自动化不达」先检查**DPI 缩放**（坐标补偿）+ **会话隔离**（EnumWindows 0）+ **bin 时间线**，三查之后再谈引擎 bug。
