# T78 实现报告：高 DPI 屏文字显示不全根治（GDI 离屏位图固定 96 DPI）

## 现象（用户反馈：文字显示不全）

150% 缩放（144 DPI 感知）显示器上引擎壳多处文本被裁/变形：
- 主菜单右区标题「功能」顶部与底部缺失（字形碎块化）；
- 玩家统计两行（「游玩 1 次 · 最高ACC 0.00%」/「累计命中 0 音符 · 最佳连击 0x」）互相压叠且上下被裁；
- 底栏提示、部分按钮/标签文本越出标签矩形被裁剪（截断/重叠的旧记录在 150% 屏复现）。

## 根因（像素级取证）

引擎壳 GDI 渲染位图 `new Bitmap(w, h)` 在 PerMonitorV2 DPI 感知进程中的**默认分辨率=显示器 DPI（本机 144）**。
GDI+ 的 `GraphicsUnit.Point` 字号按 `Graphics.DpiY`（144）换算像素：13pt→26px（应 17.3px），
而全部布局/裁剪矩形（UiLabel Clip、卡片尺寸）仍按 1280×800 **96 逻辑值**——文本比逻辑布局大 1.5×，
被标签裁剪矩形切掉（取证：`功能` 墨迹宽 50px=34px×1.5；MeasureString「功能」13pt @144dpi=62.2px vs @96dpi=41.5px）。

受影响的渲染路径（均为引擎壳 GDI/GdiDrawAdapter 上绘制文本的离屏位图）：
- 实窗 OnPaint `_gdiBmp`（用户可见主路径）；
- 转场缓存帧 CaptureCanvasFrame、背景色缓存在同 Graphics（后者无文本）；
- `--shellshot` / `--foldershot` / `--uisceneshot` 取证截图；
- `UiMeasure.GdiWidth`（1×1 测量位图——FitFont/AutoSize 测量口，必须同步 96 DPI 否则缩字号口径错位）；
- 引擎 UI 演示窗 / noteshot / storyshot / 压测（EngineStressCli / GameStressCli / StressTestCli / ParityCli / PerfTest）同口径位图。

## 修复

新增 `游戏源码\源码\CoreUtil\DpiBitmap.cs`：`DpiBitmap.Create(w,h)` = `new Bitmap(w,h)` + `SetResolution(96,96)`
（pt→px 按 96 换算，文本以逻辑尺寸进入 letterbox 变换——t27 设计「文字按字形轮廓在目标尺寸直接光栅化」，
任意 DPI 显示器与 1280×800 设计一致）。替换上述全部引擎壳 GDI 文本渲染/测量位图创建点（12 处）。

关键点：**测量与绘制必须同步 96 DPI**——若只改绘制不改 `UiMeasure`，FitFont/AutoSize 会把字号误缩 1.5×（文本过小）。

## 回归说明

- 96 DPI 机器渲染结果**逐像素不变**（SetResolution(96,96) 与该类机器 `new Bitmap` 默认值一致）；
- 仅修正 DPI>96 机器上文本被放大 1.5× 后的裁切/重叠；
- 遗留：`new Bitmap` 的纯 PrintWindow/DrawToBitmap 捕获（ChartEditorPanel/GamePanel/EngineUiDemo.Capture 等）与
  背景层缓存（无文本）不改；编辑器/游玩/WinForms 设置页为 DPI 自主缩放路径，不在本修复范围（历轮已证正常）。
