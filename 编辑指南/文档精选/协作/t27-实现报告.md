# t27 实现报告：引擎壳高分辨率渲染（取消 1280×800 位图拉伸，改物理客户区原生矢量绘制）

- 日期：2026-08-27 · 承办 coder-max · 约束：只写代码不构建（captain 构建 + 试玩定点复验）
- 变更文件：`源码/Play/EngineUi/EngineMainShell.cs`（单文件，OnPaint 绘制管线 + 3 个配合点）

---

## 根因
- 旧 OnPaint：`_gdiBmp = new Bitmap(1280, 800)` 固定逻辑分辨率 → `e.Graphics.DrawImage` 双三次拉伸到物理客户区
  （用户环境 2249×1406 等）→ 文字/UI 位图放大发虚（『分辨率低』观感）；行距在放大+发虚下呈『贴叠』观感
  （像素带实际分离——试玩 r7 已证）。

## 方案（按任务 5 条方向逐条落地）

1. **原生尺寸位图**：`_gdiBmp` 按 `PhysClient()` 物理客户区创建，尺寸变化才重建（先 Dispose 旧图/旧 Graphics），
   否则常驻复用（2560×1600 BGRA ≈ 16MB，一次性分配，任务预算 ~12MB 量级内）。
2. **矢量变换**：位图内 `ResetTransform → Clear(背景色) → TranslateTransform(tx,ty) → ScaleTransform(scale,scale)`
   （tx=(w-1280×scale)/2、ty 同公式），之后 DrawBackdrop/PaintContent/DrawTopBar 照旧——组件/字体/坐标仍是
   1280×800 逻辑值，全部经 GDI+ 世界变换按矢量路径在目标尺寸直接光栅化（文字=字形轮廓缩放，锐利非拉伸）。
3. **1:1 贴窗**：`e.Graphics.DrawImageUnscaled(_gdiBmp, 0, 0)`——像素一一对应，无二次缩放、无双三次；
   letterbox 边带由 `g.Clear(背景色)` 填充。
4. **物理语义保持**：`_w/_h` 仍为物理客户区值；新增字段 `_ltx/_lty/_lscale` 记录本帧 letterbox 变换供
   `Dim`（ResetTransform 后按 0,0,_w,_h 全位图均匀压暗，含边带）与 `RenderClippedCircle`（Save→ResetTransform→
   SetClip 物理矩形→重挂 Translate/Scale→渲染→Restore）在物理/逻辑两坐标系间正确换算；
   文字 hint 保持 AntiAliasGridFit（目标尺寸下网格拟合，锐利）。
5. **影响面**：只改 OnPaint 管线 + Dim/RenderClippedCircle/OnFormClosed 三处配合 + 3 个字段；
   组件/字体/坐标零改动，未引入任何新重叠点。

## 附带收益与关键验证
- **Graphics 常驻复用**：旧代码每帧 `using` 释放位图 Graphics，而 `_gdiAdapter`/`TopBarHit.MeasureText` 在
  帧间命中路径仍引用之（潜在 ObjectDisposed 隐患）；新代码 Graphics 随位图生命周期常驻（OnFormClosed 释放），
  隐患根治，且每帧免一次 Graphics 创建。
- **MeasureString 变换无关性已实测**：PowerShell GDI+ 探针——同一 Graphics 加 `ScaleTransform(2,2)` 前后
  `MeasureString('自动调整延迟', 14pt)` 宽度均为 121.55px（变换无关）→ UiLabel 的 AutoShrinkFont/居中/Ellipsis
  等布局数学仍以逻辑单位计算，字号/折行/截断零回归，不会因放大触发误缩字号。
- **转场语义**：CircleReveal 圆心=物理中心=letterbox 内容中心（修正旧代码在 1280×800 位图上用物理 _w 造成的
  圆心偏移）；Slide 距离沿用 _w 物理语义，视觉不变。
- **取证路径不变**：`RenderPageTo`/`--shellshot`/`--foldershot` 走无变换离屏 1280×800 GDI 渲染，
  试玩既有像素带取证口径不受影响。

## 性能预判（captain 构建后实测口径）
- 成本增量 = 填充面积（Clear+背景渐变按物理面积）+ 字形在目标尺寸光栅化（每帧一次）；GDI 填充速率高，
  量级仍在 16ms 定时器预算内（引擎壳帧率本就 16ms 定时器 ~62fps 上限，无新增依赖）。
- 游玩 fps（FpsGovernor 1000+ 档）不在本改动面内，零影响。

## 试玩复验口径（captain 构建后）
1. 最大化（用户环境）+ 1920/2560 两档：文字边缘对比采样——锐度显著优于旧位图拉伸（无发虚）。
2. 逐页零重叠复查（主菜单/选歌/设置 9 分区/次级页）：本改动不移动任何元素，重叠指标应与 r7 基线一致。
3. F1 菜单条、页面转场（CircleReveal/Slide/Fade）、窗口尺寸变更/全屏切换无残影/无黑边。
4. fps 指标（shell 帧时间 P99 与帧内存；游玩 fps≥1000 保持）。
